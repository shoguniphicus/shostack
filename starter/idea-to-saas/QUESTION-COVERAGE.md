# Question coverage — silent agent checklist, not a questionnaire

**DO NOT paste this list to a user in the opening turn.** Each category is conditional. The aim is eventual discovery of consequential realities, not forced selection of irrelevant technologies.

For each category in a PRODUCT record, mark **explored**, **material unknown**, **deferred with reason**, or **not applicable**. Revisit when user steering, a new journey or production risk changes the answer.

| Area | Listen for | One useful contextual probe |
| --- | --- | --- |
| **Pain and trigger** | Friction, repeated manual work, confusing process, emotional or financial cost | "Tell me the last time this problem happened. What triggered it?" |
| **Actor, beneficiary, payer** | Users, admins, buyers, parents, staff, operators, guests | "Who experiences the problem, and who would approve spending to solve it?" |
| **Workaround and substitutes** | Sheets, WhatsApp, competitor SaaS, outsourced work, manual staff | "How does this job get done today when your product doesn't exist?" |
| **Existing alternatives** | Competitors, embedded feature, in-house process | "Why wouldn't they keep using their current workaround?" |
| **Feature versus product** | Small enhancement within an existing tool, unwillingness to switch | "Would the user buy this separately, or expect it inside a tool they already pay for?" |
| **Problem importance** | Frequency, severity, urgency, willingness to change | "What breaks if they do nothing for another six months?" |
| **Discovery and distribution** | Who will hear about it; trust and access | "How would the first ten real users find it?" |
| **Adoption and friction** | Login fatigue, training, imports, staff resistance | "What is the smallest thing someone must do before getting value?" |
| **Willingness to pay** | Stated interest versus behavior, economic buyer, buyer resistance | "What would you need to observe before believing they will pay?" |
| **Economic viability** | Cost per workflow, provider bills, refunds, support load | "Which activities might get more expensive as usage rises?" |
| **First meaningful outcome** | Concrete completion, result and time to value | "What would someone achieve in their first successful session?" |
| **End-to-end journey** | Before, trigger, action, review, downstream operation | "Walk me through one case from start to finish, including what happens after the screen closes." |
| **Exceptions and recovery** | Missing input, duplicate, timeout, cancellation, dispute | "What happens when that normal flow fails or somebody changes their mind?" |
| **Ownership and authority** | Owner, staff, admins, moderator, operator | "Who gets to make that decision or override the agent?" |
| **Workspace and tenancy** | One user, shared teams, separate organizations and guests | "What must one group never see or edit from another group?" |
| **Information and data rights** | Uploads, private records, copyright, consent, retention | "Who owns the material and who may use or delete it?" |
| **Privacy, trust and regulation** | Personal data, children, finances, external sharing | "What information would harm someone if exposed or handled incorrectly?" |
| **External dependencies** | Payment service, ERP, email, WhatsApp, AI providers | "What must another system do before your flow can finish?" |
| **Source of truth** | Duplicate or conflicting data between systems | "If two screens disagree, which one is authoritative?" |
| **Lifecycle and status** | Draft/review/approved/published/withdrawn, jobs/requests | "Which states must a user be able to recognize and recover from?" |
| **Access and security** | Auth, roles, privileges, fraud, identity | "Who is allowed to trigger an action with a real cost or lasting effect?" |
| **Reliability and scale** | Delays, jobs, spikes, real-time needs and failure budgets | "How long can this take before the outcome stops being useful?" |
| **Operations and support** | Manual intervention, customer service, monitoring, incidents | "Who notices if the process silently stops working?" |
| **Analytics and learning** | Early signals, adoption, retention, user feedback | "What observation would persuade you to continue or abandon this direction?" |
| **Accessibility and environments** | Mobile bandwidth, devices, language, assisted use | "What kind of device and situation will the actual user have?" |
| **Non-goals and scope** | Feature creep, artificial sophistication | "What looks tempting but absolutely does not belong in the first slice?" |
| **Assumptions and alternatives** | Premature stack, fashionable architecture | "What simpler option could produce the same result and what would it lose?" |
| **Acceptance and verification** | Runnable test path, mock boundary, prototype learning | "What would we show or check to know we solved the smallest real problem?" |
| **Release and rollback** | Contracts, deployment, migration, operational exposure | "If a new release is wrong, how will users and operators recover?" |

## Prioritization rule

Ask the question with the best combination of **decision impact, risk of being wrong, and ease of answering now**, while respecting founder attention. Prefer concrete examples over abstract questions. Don't ask about infrastructure when a basic actor/use case question could invalidate the product. Don't postpone a material consent/authority question when a proposed live action would cross that boundary.

A missing answer can legitimately stay unknown, be marked deferred, or become an experiment. It must not silently be inferred from product convention.
